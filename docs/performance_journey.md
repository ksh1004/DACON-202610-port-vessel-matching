## 한눈에 보기

| 버전 | 핵심 변경 | Public | 변화 | test 한글 추정* |
|---|---|---|---|---|
| baseline | 공식 베이스라인 (후보 검색 + RandomForest) | 0.3616 | | ≈ 0.10 |
| v2 | LightGBM LambdaRank 재순위 | 0.4981 | +0.137 | ≈ 0.28 |
| v3 | 한글 → 영문 **발음 키** 매칭 | 0.7408 | +0.243 | ≈ 0.63 |
| v4 | **노이즈 증강** (톤수 결측, 오타, 약칭) | 0.8289 | +0.088 | ≈ 0.76 |
| v6 | **LLM 음역** (Kanana-1.5-2.1B) | 0.8979 | +0.069 | ≈ 0.855 |
| v7 | 약칭 검색 + 사전정보 특징 + **CatBoost 앙상블** | **0.8998** | +0.002 | ≈ 0.858 |
| v8 | v7 + CatBoost 증강 시드 3개 평균 | 0.8987 | -0.001 | ≈ 0.857 |

\* 비한글 test 정확도를 0.998(CV 값)로 두고 Public에서 역산한 값

제출은 6회(하루 5회 제한)만 사용했습니다. 진단용 제출은 하지 않았고, 모든 결정은 로컬 검증으로 내렸습니다.

## 최종 구조 (v7)

```
입항 기록 1행
 ├─ 1단계 후보 검색 (질의마다 약 180개, 행 독립)
 │    영문 문자 n-gram TF-IDF · 정확 일치 · 총톤수 근접
 │    한글: 발음 키 TF-IDF (전체 / 단어 단위) · LLM 음역 4개로 영문 검색
 │    약칭: 남은 단어를 모두 포함하는 선박 중 톤수가 가까운 순 (톤수가 없으면 선종·국적 순)
 └─ 2단계 재순위 (특징 78개)
      CatBoost YetiRank ×3 + LightGBM LambdaRank (증강 시드 7, 8)
      → 질의 그룹 안에서 softmax 정규화 후 가중 합 → 1등 vessel_id
```

---

## 1단계: 문제 분해와 재순위 모델 (baseline → v2, +0.137)

- **문제 분해**: train의 한글 기록은 9.7%뿐인데 점수 가중치는 70%입니다. 카탈로그 이름은 100% 영문입니다. 그래서 문제를 "한글 음역 매칭"과 "영문 오타 매칭" 두 갈래로 나눴습니다.
- **검증 체계**: 선박(`call_sign`) 단위 5-fold. 같은 선박이 학습과 검증에 동시에 들어가지 않습니다.
- **2단계 구조**: 여러 검색기의 합집합으로 후보를 만들고(비한글 recall 0.999), LightGBM LambdaRank로 1등을 고릅니다.
- **결과**: OOF 비한글 0.998. 한글은 이름 신호가 없어 톤수·선종·국적만으로 0.41에 그쳤습니다.

**배운 점**: 검증 fold로 early stopping을 하면 OOF가 부풀려집니다(0.606 → 반복 수 고정 시 0.589). 작은 집단일수록 노이즈를 "최적"으로 고르게 됩니다.

## 2단계: 한글 발음 키 (v3, +0.243)

- 한글 이름의 원천은 영어 외래어, 한국어 로마자, 중국어 병음, 일본어, 알파벳 읽기(`케이엠티씨 → KMTC`)로 다양합니다.
- 공통 표현으로 **자음 골격 발음 키**를 설계했습니다. 예: `모닝 → MNN`, `Morning → MNN`. 규칙만 쓰므로 학습 데이터가 필요 없습니다.
- 규칙을 반복 개선해 키 정확 일치율을 78% → 87%로 올렸습니다.
- **결과**: OOF 한글 0.413 → **0.966**. 그런데 Public으로 역산한 test 한글은 0.63으로, CV와 차이가 컸습니다.

## 3단계: CV와 Public 차이 찾기, 노이즈 증강 (v4, +0.088)

- **스트레스 테스트**: 검증 행에 변형을 가해 하락 폭을 쟀습니다. 총톤수 결측이면 0.966 → 0.539, 단어 생략(약칭)이면 0.441로 떨어졌습니다.
- 원인: **train 한글 기록은 총톤수가 결측인 경우가 없고**, 약칭도 없습니다. 모델이 톤수에 기대는 법만 배웠습니다.
- **노이즈 증강**: 한글 행당 4개, 영문 행당 1개의 노이즈 복사본(톤수 결측·오차, 오타, 단어 생략, 국적 결측)을 만들어 원본과 같은 fold에만 넣었습니다.
- **결과**: 원본 CV는 그대로인데 강건성이 올라갔습니다(톤수 결측 0.539 → 0.856). Public +0.088로 가설이 맞았음을 확인했습니다.

**배운 점**: 원본 CV가 오르지 않는 개선도 test에서는 클 수 있습니다. 평가 축(스트레스 테스트)을 따로 만들어야 보입니다.

## 4단계: LLM 음역 (v6, +0.069)

- 공개 소형 LLM 5종을 "한글 → 영문 생성 → 카탈로그 검색" 방식으로 비교했습니다.
  - 한국어 특화 모델이 2배 큰 범용 모델보다 좋았습니다 (Kanana-2.1B 검색 상위 10위 0.927, Qwen3-4B 0.887).
  - 속도까지 고려해 Kanana를 선택했습니다.
- **결정성 검증**: 여러 이름을 한 배치로 생성하면 패딩 때문에 결과가 바뀌었습니다(48개 중 2~3개). 대회의 행 독립 규칙을 지키려고 **배치 1**로 생성합니다.
- LLM 후보 4개를 검색과 특징 11개에 사용했고, 같은 이름의 결과는 캐시합니다.
- **결과**: OOF 0.976 → 0.995, 톤수 결측 0.830 → 0.968. Public **0.8979**, 서버 8분.

**배운 점**: 규칙(발음 키)과 LLM은 경쟁이 아니라 보완 관계였습니다. 둘을 합치면 상위 10위 recall이 0.80 → 0.96이 됩니다. 최종 판단은 재순위 모델에 맡겼습니다.

## 5단계: 제출 점수로 test 구성 역추정

- train의 실제 노이즈를 측정했습니다.
  - 비한글은 선박 단위로 35%에 글자 삭제·중복·순서 바뀜이 있고, **단어 생략은 0건**입니다.
  - 한글 이름은 깨끗합니다.
- v2·v3·v4·v6의 Public 점수를 "모델별 시나리오 정확도의 혼합"으로 놓고 비음수 최소제곱으로 풀었습니다.
  - 결과: test 한글 ≈ **원본 44%, 톤수 결측 14%, 단어 생략 23%, 둘 다 19%**
  - 비한글 정확도 가정을 0.97~0.998로 바꿔도 거의 같았습니다.
- 결론: v6의 남은 손실 대부분이 **약칭 행**에서 나옵니다. train에는 약칭이 없어서 CV로는 보이지 않았습니다.

**배운 점**: 제출 하나하나를 "어떤 시나리오에서 몇 점인 모델"로 기록해 두면, Public 점수 여러 개를 연립방정식처럼 풀어 숨겨진 test 분포를 추정할 수 있습니다. 진단용 제출 없이 방향을 정했습니다.

## 6단계: 약칭 대응과 정보 한계 확인

- **단어 포함 + 톤수 근접 검색기**: 남은 단어를 모두 포함하는 선박을 톤수가 가까운 순으로 찾습니다(오타 1글자 허용).
  - 약칭 행의 후보 recall: 0.831 → **0.964** (톤수 있음), 0.756 → **0.904** (톤수 없음)
- 그런데 **정확도는 거의 그대로**였습니다(약 +0.002).
- 원인: 오답의 80%는 예측 선박의 톤수가 정답보다 같거나 더 가까웠습니다. 행에 있는 정보로는 구분할 수 없는 **자매선**입니다(예: `모닝` + 60,876톤 → 같은 설계의 Morning 선박 여러 척).
- 이상적 규칙(이름을 완벽히 이해하고 선종·국적 매핑이 가장 높은 선박 선택)의 상한도 0.425로, 모델(약 0.40)과 차이가 작았습니다.

**배운 점**: recall이 올라도 정확도가 오르지는 않습니다. 개선 실험 전에 "정보 상한"을 먼저 계산하는 것이 시간을 아낍니다.

## 7단계: test 유사 평가 세트와 앙상블 (v7, +0.002)

- **test 유사 평가 세트**: train 한글 1,191행을 5단계의 test 구성대로 변형하고 가중했습니다.
  - 현재 단일 모델 0.8951, 실제 v6 Public 0.8979 → **Public과 잘 맞는 지표**
  - 400행 스트레스 표본보다 3배 큽니다.
- **오프라인 블렌딩**: 실험마다 후보별 점수를 저장해, 재학습 없이 조합을 평가했습니다. 정규화는 질의 그룹 안에서만 하므로 행 독립입니다.
- **후보 사전정보 특징**: 실제 입항 선박에 흔한 국적·선종인지(관측 / 기대 정답 수, fold마다 다시 적합), 카탈로그 크기·단위

| 모델 | test 유사 | hard | OOF |
|---|---|---|---|
| LightGBM (기존 설정) | 0.8951 | 0.8388 | 0.9953 |
| LightGBM 변형 7종끼리 블렌딩 | 최고 0.8972 | | |
| CatBoost YetiRank + 사전정보 특징 | 0.9017 | 0.8444 | 0.9947 |
| **v7: CatBoost ×3 + LightGBM 증강 시드 7·8 (softmax)** | **0.9020** | 0.8440 | **0.9965** |

- 제출 검사 통과: 3,000행 167초 (서버 약 9분 예상, 제한 30분), 행 독립성 OK, zip 4.4GB
- **실제 결과**: Public 0.8998 (+0.0019, 서버 8분 38초). 예측(+0.007)보다 작지만, public 한글 1행이 0.0023 이상이라 차이는 1~2행 수준입니다. testlike의 오차 폭은 약 ±0.003으로 확인했습니다.

**배운 점**
- 같은 특징을 쓰는 LightGBM 변형끼리는 같은 곳에서 틀려서 앙상블 효과가 작았습니다(+0.002). **다른 알고리즘(CatBoost)** 을 섞었을 때 효과가 컸습니다(+0.006).
- 조합을 20여 개 비교하면 최고값이 선택 편향으로 부풀려집니다. 그래서 여러 지표에서 고르게 좋은 조합을 골랐습니다.

| 시도 | 결과 | 이유 |
|---|---|---|
| 재순위 학습기 하이퍼파라미터 변경 | ±0.002 | 입력 신호가 같으면 학습기 변경 효과가 작음 |

## 전체에서 얻은 교훈

1. **입력 신호가 모델보다 중요했습니다.** 발음 키 +0.24, 증강 +0.09, LLM +0.07에 비해 학습기 변경은 ±0.002였습니다.
2. **CV가 포화되면 새 평가 축을 만들어야 합니다.** 스트레스 테스트 → hard 세트 → test 유사 세트 순으로 발전시켰습니다.
3. **제출은 실험입니다.** 한 번에 한 요소만 바꾼 제출 기록을 모아 test 분포를 역추정했습니다.
4. **정확도가 안 오르면 정보가 충분한지 먼저 봐야 합니다.** 개선 전에 정보 상한을 계산하는 습관이 필요합니다.
5. **규칙 준수(행 독립성, 결정성)를 자동으로 검사합니다.** LLM 배치 생성처럼 성능 최적화가 규칙 위반의 원인이 될 수 있습니다.

## 남은 과제

- Public 해상도(한글 1행 ≈ 0.0023)를 고려해, 로컬 지표에서 +0.005 이상일 때만 제출
- CatBoost 변형·시드 추가 (가장 강한 단일 알고리즘)
- LLM 추론 속도 개선 (동점일 때 추론 시간이 순위를 결정)
