## 1. 공식 페이지에서 확인한 사실

- 평가식은 `0.7 × 한글 기록 정확도 + 0.3 × 비한글 기록 정확도`다. Public은 test의 50%, Private은 전체 test다. 온라인 예선은 종료 시점 Public을 사용한다. 서버는 L4 22.4GiB, 추론 전체 제한은 30분이다. [공식 평가 안내](https://dacon.io/competitions/official/236771/overview/evaluation)
- **실제 test 행 수는 공개하지 않는다.** `sample_submission.csv`의 행 수·ID·값은 실제 평가 데이터의 규모·ID·정답을 나타내지 않는다. 기존 개요의 “test 3,000행”, 그로부터 계산한 Public 한글 300행 이하 및 한 행당 약 0.0023점 추정은 근거가 부족하다. 3,000행은 로컬 실행 검사용 표본 크기로만 사용한다. [공식 데이터 설명](https://dacon.io/competitions/official/236771/data)
- 추가 학습·검증 데이터는 공식 train과 catalog로 제한되고 공개 범용 사전학습 가중치는 사용할 수 있다. 다른 test 행이나 test 전체 분포를 이용하는 예측 보정은 금지된다. [공식 규칙](https://dacon.io/competitions/official/236771/overview/rules)
- 조회 시점 리더보드 1위는 **0.98549**, 6위는 **0.98022**다. 0.97 이상 제출은 존재한다. 그러나 점수만으로 상위 팀의 입력 신호·방법이나 코드 검증 결과를 알 수 없다. “호출부호를 썼다” 또는 “호출부호 없이도 된다”는 결론 모두 아직 입증되지 않았다. [공식 리더보드](https://dacon.io/competitions/official/236771/leaderboard)

호출부호 조회 및 익명화 일관성에 관한 [공개 질문](https://dacon.io/competitions/official/236771/talkboard/418273)도 확인했으나, 이번에 읽은 비로그인 페이지에서 운영진 답변을 확인하지 못했다. 질문 게시글 자체를 허용 근거로 사용하지 않는다. 카탈로그의 사전 한글 변환·증류도 [별도 질문](https://dacon.io/competitions/official/236771/talkboard/418272)이 있어, 이를 공식 승인된 방법으로 간주하지 않는다.

## 2. 0.97이 요구하는 개선 규모

비한글 정확도를 현재 로컬 수준인 0.9981로 가정하면 필요한 한글 정확도는 다음과 같다.

`(0.97 - 0.3 × 0.9981) / 0.7 = 0.95796`

v7 Public 0.8998에서 0.97까지는 **+0.0702**이며, 현재 가중 오차의 **70.1%**를 줄여야 한다. 이 비율은 한글·비한글 행 수를 추정하지 않고도 계산할 수 있다. 비한글 성능이 0.9981이라는 가정은 실제 test에서 확인된 값이 아니다.

따라서 기존 앙상블의 +0.002~0.003을 반복하는 계획만으로는 목표를 뒷받침할 수 없다. 이미 v8은 로컬 0.9050, Public 0.8987로 측정됐다. 미세한 로컬 개선이 Public 상승으로 이어진다는 가정도 성립하지 않았다.

## 3. 정답 선택 오라클로 확인한 후보 범위

[probe_target97.py](../tools/probe_target97.py)로 기존 OOF 점수와 후보를 다시 읽어 계산했다. 한글 시나리오와 혼합 가중은 기존 testlike와 동일하며, 비한글 예측은 각 모델의 기존 top1을 고정한다. 결과는 [target97_audit.json](../experiments/target97_audit.json)에 저장했다.

| 허용 후보 범위 | v7 testlike | v8 testlike |
|---|---:|---:|
| 현재 top1 | 0.9020 | 0.9050 |
| 상위 2개 안에서 정답을 항상 선택 | 0.9334 | 0.9341 |
| 상위 5개 안에서 정답을 항상 선택 | 0.9651 | 0.9668 |
| 상위 10개 안에서 정답을 항상 선택 | 0.9817 | 0.9813 |
| 상위 20개 안에서 정답을 항상 선택 | 0.9904 | 0.9890 |
| 전체 후보에서 정답을 항상 선택 | 0.9957 | 0.9957 |

이 표는 **정답을 아는 선택기의 값**이며 실제 모델의 성능 예측이 아니다. 다만 다음 설계 결정은 가능하다.

1. **현재 top5 안에서만 선택하는 구조는 로컬에서조차 0.97에 못 미친다.** 이전 개선안의 top5 중심 판별기는 목표에 맞게 범위를 넓혀야 한다.
2. 0.97을 지향하는 판별기는 top20 정도에서 출발하는 것이 타당하다. top10은 오라클도 약 0.981이라 여유가 작다. v8 기준 top10에서 회복 가능한 가중 개선의 약 85%, top20에서는 약 77%를 실제로 회복해야 0.97이 된다.
3. 전체 후보 recall은 충분히 높다. 현재 최대 병목은 후보 포함 이후의 정답 구별이다. 그러나 잘못된 순위를 바꾸는 학습이 성공한다는 증거는 아직 없다.

예전의 특정 규칙 정확도 0.425는 정보이론적 상한이 아니다. 반대로 위 오라클 0.99도 관측 필드만으로 그 성능이 달성 가능하다는 증거가 아니다.

## 4. 이번에 실제로 시험한 새 방식

기존 Kanana 가중치를 사용해 한글 기록과 상위 10개 후보의 이름·톤수·선종·국적을 함께 제시했다. 모델은 정답 후보의 선택지 문자 확률을 한 번의 forward로 계산했다. 호출부호, sample_id, vessel_id, 정답, 기존 후보 순위는 모델 입력에서 제외했다. 후보는 고정 카탈로그 순서로 제시했다.

- 톤수 결측 / 실제 단어 생략 / 실제 단어 생략+결측에서 각각 20행, 총 60행.
- 예측 정오를 보지 않고 고정 시드로 추출하고, 시나리오별 선박 중복 및 few-shot 12척을 제외했다. 시나리오 사이에는 같은 선박이 포함될 수 있다.
- 기존 v7, LLM 단독, 고정 비율 블렌딩(기존 75% + LLM 25%)을 비교했다.
- 새 가중치 다운로드나 파인튜닝은 수행하지 않았다.

| 시나리오 | v7 | LLM 직접 선택 | 25% 블렌딩 |
|---|---:|---:|---:|
| 톤수 결측 20행 | 19/20 | 12/20 | 19/20 |
| 실제 단어 생략 20행 | 15/20 | 5/20 | 14/20 |
| 실제 단어 생략+결측 20행 | 8/20 | 3/20 | 7/20 |

**이 프롬프트의 무학습 LLM 직접 선택은 확대하지 않는다.** 후보가 있는 상황에서도 강건한 선택 신호를 주지 못했다. 이는 다른 프롬프트·지도학습 판별기 전체의 실패를 증명하는 결과는 아니다.

60행 forward 구간은 로컬 11.9초, 약 0.20초/행이었다. 로딩·후보 생성은 포함하지 않았고 서버 측정값도 아니다. 작은 층화 표본이므로 이 정확도를 testlike나 Public 추정치로 변환하지 않는다.

## 5. 호출부호 없이 진행할 실험 순서

### A. 평가 가정을 다시 검증한다

현재 44/14/23/19% 혼합비는 소수 Public 결과로 맞춘 가설이다. 실제 test에서 같은 비율이나 같은 노이즈가 발생한다고 확인된 적이 없다. 기존 지표는 회귀 확인용으로 유지하되, 그것만 올리는 모델 선택은 중단한다.

- 후보 검색의 범주 정렬 매퍼를 학습 fold에만 적합해 후보 집합·`rank_tok`까지 독립적으로 생성하는 기준 평가를 만든다.
- 원본·한글 오타·붙여쓰기·단어 생략·숫자/약어 변형·각 톤수 필드의 개별 결측/오차를 따로 측정한다. 기존 증강은 두 톤수 필드가 함께 사라지거나 같은 비율로 변하는 경우에 집중돼 있다.
- 실제 이름이 변형된 행과 no-op 행을 분리하고, 새 고정 변형 시드의 세트를 최종 비교용으로 보관한다.
- few-shot 선박 전체를 제외하고 선박 단위로 오차를 묶는다. 숫자 ID나 동일 선박의 train 조회로 성능을 올리는 경로는 제외한다.

이 단계의 목적은 0.97을 만들기 쉬운 검증을 고르는 것이 아니라, 현재 0.90의 원인을 합성 노이즈의 특정 가정에만 귀속시키지 않는 것이다.

### B. 상위 20개에 대한 지도학습 판별기를 시험한다

현재 특징은 문자열/발음 키/4개 음역 빔의 유사도를 압축해 사용한다. 새로운 모델은 **기록 문자열과 후보 문자열 자체를 함께 읽어** 어떤 음절·숫자·남은 단어가 맞는지 학습하도록 한다.

- 예: 공개 범용 다국어 사전학습 가중치로 시작하는 작은 교차 인코더. Qwen3-Reranker-0.6B는 100개 이상 언어와 사용자 지정 지시문을 지원하는 후보지만, 선박 식별 성능은 별도 검증해야 한다. [제작자 모델 카드](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B)
- 학습은 공식 train의 정답 쌍과 catalog의 음성 후보, 공식 행의 증강만 사용한다. 외부 선박 사실이나 별도 정답 데이터는 넣지 않는다.
- 학습 fold 내부의 예측으로 혼동 후보를 만든다. 외부 검증 정답을 보고 음성 후보를 최적화하거나 메타 모델을 학습하지 않는다.
- 정답을 학습 후보에 보강할 수는 있지만 평가 후보에 강제로 넣지 않는다. top20에 정답이 없는 실패도 평가에 그대로 남긴다.
- 이름/음역 구별 점수와 기존 톤수·범주 특징을 결합한다. 이름만으로 자매선을 식별할 수 있다고 가정하지 않는다.

**첫 채택 기준:** 별도 검증 선박의 중간 규모 표본에서 기존 정답을 유지하면서 약칭 오답을 순증으로 회복하는지 확인한다. 실패하면 전체 5-fold나 장시간 파인튜닝으로 확대하지 않는다. 통과하면 독립 fold와 새 노이즈 세트로 확대한다.

계획 작성 당시에는 미구현이었다. 이후 5-fold 학습·평가를 완료했으며, 결과와 한계는 상단 실행 결과와 [실행 기록](implementation_run_20261027.md)에 반영했다.

### C. 제원 오차의 조건부 신뢰도를 보강한다

이름 판별기가 단서를 주는 행에서는 `이름이 비슷한 후보 사이의 톤수 차이`, `선종별 톤수 오차`, `기록 국적과 후보 국적의 불일치 신뢰도`, `두 톤수 필드의 모순`을 함께 학습한다. 후보 ID 자체를 외우는 사전이나 연도별 선박 정답 조회는 사용하지 않는다.

기존 모델에도 톤수와 범주 확률이 있으므로 이 변경만으로 +0.07을 기대하지 않는다. 문자열 판별기가 고친 후보를 제원으로 다시 검증하는 역할이다.

### D. 추론 제약에 맞춰 확장한다

고정된 행별 모호성 기준으로 어려운 행만 추가 판별기에 보낼 수 있다. 다른 test 행이나 실행 순서에 따라 기준을 바꾸거나 “앞 N행까지만 LLM 실행”하는 방식은 행 독립성과 맞지 않는다. 모든 후보 점수 계산과 분기는 해당 행·공식 catalog·고정 학습 산출물만 사용해야 한다.

실제 test 행 수가 비공개이므로 3,000행 시간만으로 전체 30분 통과를 보장하지 않는다. 로컬 표본의 한글 비중·고유 이름 수에 따른 처리량, 모델 로딩 시간, 메모리 사용을 별도로 측정한다.

## 6. 현재 판단

**0.97은 목표로 유지하지만, 호출부호 제외 조건에서 도달 경로는 아직 입증되지 않았다.** 현 상태에서 약속할 수 있는 예상 점수가 아니다. 재순위 가능한 후보 범위와 추가로 필요한 오차 회복량은 확인했고, 단순 LLM 후보 선택은 실제 시험에서 기각했다.

다음 의사결정은 “상위 20개 지도학습 판별기가 독립 검증에서 새로운 정답 구별 신호를 만드는가”다. 실패할 경우 더 많은 동일 계열 앙상블로 목표를 달성할 수 있다고 가정하지 않는다. 이번 작업에서는 배포 모델·제출 ZIP을 수정하거나 제출하지 않았다.
