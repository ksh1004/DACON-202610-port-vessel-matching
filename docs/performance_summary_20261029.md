## 1. 전체 흐름

성능 개선은 **후보 검색·순위 학습 → 한글 발음 표현 → 결측·약칭 증강 → LLM 음역 → 지도학습 후보 판별** 순서로 진행됐다. 이후에는 학습량·결합 구조·이름 모델·학습 손실·제원 통계를 바꾸는 실험을 수행했다.

실제 Public은 베이스라인0.3616에서 v12의0.9065951735까지 약0.5450 상승했다. 큰 폭의 상승은 한글 발음 처리, 노이즈 증강, LLM 음역을 도입한 단계에서 발생했다. 이후에는 특정 상황의 개선과 다른 상황의 회귀가 함께 나타나 순증을 얻기 어려워졌다.

| 단계 | 주요 변경 | 실제 Public | 서버 실행 시간 |
|---|---|---:|---:|
| baseline | 공식 후보 검색 + RandomForest | 0.3616 | 8초 |
| v2 | 후보 검색 + LightGBM LambdaRank | 0.4981 | 32초 |
| v3 | 한글·영문 자음 골격 발음 키 | 0.7408 | 48초 |
| v4 | 톤수 결측·오차, 오타·단어 생략 증강 | 0.8289 | 58초 |
| v6 | Kanana 영문 음역 4개를 검색·특징에 활용 | 0.8979 | 8분 8초 |
| v7 | 약칭 검색·사전통계·CatBoost/LightGBM 앙상블 | 0.8998 | 8분 38초 |
| v8 | 증강 시드가 다른 CatBoost 모델 추가 | 0.8987 | 8분 39초 |
| v11 | 음역 입력과 혼동 후보를 학습한 Qwen 판별기 | 0.9039635945 | 9분 31초 |

위 표는 실제 제출9회의 기록이다. v11·v12의 점수와 서버 시간은 사용자 보고값이다. v1·v5는 진단·개선 실험으로 제출하지 않았고, v10은 패키지를 준비했지만 제출하지 않았다. 호출부호 조회를 사용하는 v9도 현재 제출 후보에서 제외했다. [원본 제출 기록](../experiments/submissions.md)

## 2. 문제를 어떻게 나누었는가

입항 기록 한 행을 공식 카탈로그의 선박 ID 하나에 연결하는 문제다. 공식 학습 기록은12,222행, 카탈로그는78,595척이다. 학습 기록 중 한글 이름은1,191행·382척으로 비중이 작지만, 평가 점수는 **한글 정확도70% + 비한글 정확도30%**다.

따라서 한글 이름을 영문 카탈로그와 연결하는 능력에 우선순위를 두었다. 비한글 이름은 문자열 검색으로 높은 정확도를 확보하고, 한글 이름은 발음·음역·제원을 조합해 후보를 찾고 재판별하는 방식으로 발전시켰다.

## 3. 실제 점수가 오른 단계

### 3.1. 후보 검색과 순위 학습: baseline → v2

여러 검색기의 후보를 모은 뒤 LightGBM LambdaRank가 정답 후보를 위로 올리도록 학습했다. 비한글 매칭은 개선됐지만, 한글에는 직접적인 이름 비교 신호가 부족했다. Public은0.3616에서0.4981로 상승했다.

### 3.2. 한글·영문의 공통 발음 표현: v3

한글과 영문을 비교할 수 있도록 자음 골격 발음 키를 만들었다. 예를 들어 `모닝`과 `Morning`을 공통 발음 표현으로 옮긴다. 검색과 후보 특징에 이 표현을 넣어 Public이0.7408까지 상승했다.

다만 원본 검증 성능에 비해 Public이 크게 낮았다. 깨끗한 학습 기록에서의 높은 정확도만으로 실제 평가 상황을 설명하기 어려워졌다.

### 3.3. 결측·약칭에 견디는 학습: v4

검증 기록에 톤수 결측과 단어 생략을 가하자 성능이 크게 하락했다. 학습 한글 기록에서는 잘 드러나지 않던 취약점이었다.

톤수 결측·오차, 국적 결측, 오타, 단어 생략을 학습에 증강하고 약칭 검색을 보강했다. 원본 검증 점수의 변화는 작았지만 스트레스 상황의 정확도가 개선됐고, Public은0.8289로 상승했다.

### 3.4. 범용 LLM의 음역 활용: v6

공개 소형 LLM을 비교한 뒤 Kanana-1.5-2.1B를 선택했다. 한글 이름에서 영문 음역 후보4개를 생성하고, 이를 카탈로그 검색과 유사도 특징에 사용했다. 규칙 기반 발음 키도 함께 유지했다.

이 단계에서 Public이0.8979로 상승했다. 배치 생성 시 결과가 달라지는 사례를 확인해 생성 배치를1로 고정하고 행 독립성을 검사했다.

### 3.5. 약칭 검색과 앙상블: v7·v8

남은 단어를 포함하는 후보를 톤수·범주 정보로 찾는 검색기를 보강하고, 국적·선종의 학습 통계와 후보 속성을 추가했다. CatBoost와 LightGBM의 질의별 점수를 결합해 v7 Public0.8998을 얻었다.

증강 시드를 추가한 v8은 로컬 testlike가0.9020에서0.9050으로 올랐지만 Public은0.8987로 내려갔다. **로컬 상승이 실제 제출 상승으로 이어지지 않는 사례**를 확인했다. 이후 v8은 신경망 판별기의 기본 앵커로 활용했다.

### 3.6. 지도학습 후보 판별: v10·v11

기본 모델의 상위20개 후보에 Qwen3-Reranker-0.6B를 적용했다. 이름·제원·질의별 음역과 후보를 비교하고, 학습 선박에서 얻은 혼동 후보를 음성으로 사용했다.

v10은 로컬 검증·패키지 준비까지 진행했고, 음역 입력과 혼동 후보를 보강한 v11을 실제 제출했다. v11 Public은0.9039635945, 서버 시간은9분31초였다. [v11 상세](pair_iteration_20261027.md)

### 3.7. 발음 키 BGE와 Qwen 결합: v12

일반 BGE 인코더는 강건성·fold별 기준을 통과하지 못했다. 이후 한글·영문 발음 키를 입력에 명시하고 Qwen과 고정 비율로 결합한 구성이 채택됐다.

현재 구성은 **v8 75% + v11 Qwen 12.5% + 발음 키 BGE 12.5%**다. 한글 입력의 상위20개를 재판별하고, 비한글은 기존 경로를 유지한다.

| 지표 | v11 | v12 |
|---|---:|---:|
| 실제 Public | 0.9039635945 | **0.9065951735** |
| 서버 실행 시간 | 9분31초 | 9분51초 |
| 전체5-fold testlike | 0.908762 | **0.911871** |
| 전체5-fold hard | 0.854115 | **0.857935** |
| 전체5-fold 원본 OOF | 0.997693 | 0.997693 |

실제 Public은+0.0026315790, 서버 시간은+20초다. 로컬에서는 톤수 결측과 생략+결측이 개선됐지만, 톤수가 남은 단어 생략은 일부 악화했다. 별도1,596행 진단도18행 회복·19행 손실이었다. 이 한계까지 포함해 v12를 현재 최고로 보존하고 있다. [v12 상세](encoder_iteration_20261027.md)

## 5. 검증 체계와 해석할 때의 주의점

| 평가 | 목적 | 해석 범위 |
|---|---|---|
| 선박 단위5-fold OOF | 같은 선박의 학습·검증 중복을 막고 원본 성능 확인 | 깨끗한 기록에서 높아도 결측·약칭 강건성은 별도 |
| hard | 오타·약칭·톤수 결측 등의 고정 변형 평가 | 실제test의 전체 분포를 뜻하지 않음 |
| testlike | 원본·결측·단어 생략·둘 다를 가중한 비교 | 실제test 구성으로 확인된 값이 아닌 합성 대체 지표 |
| 별도 변형 진단 | 다른 변형·시드와 학습 전용 검색/매퍼에서 회귀 확인 | 반복 사용한 선박이 포함돼 완전 미관찰 평가로 부르지 않음 |
| 실행·패키지 검사 | 저장·재로딩, 행 역순/부분집합/단독, 실제 모델 호출 확인 | 구현 검증이며 성능 개선의 증거와 구분 |

testlike의 가중치는 원본44%·톤수 결측14%·단어 생략23%·둘 다19%다. 과거 제출 점수에서 역추정한 가정이며 실제test의 구성비가 아니다. 실제test 행 수와 Public 점수의 행당 해상도도 확인되지 않았다. 초기 문서의 `한글1행≈0.0023` 해석은 확정 사실로 사용하지 않는다.

또한 검증을 반복해 사용한 선택 편향과, 기준 모델의 후보 검색 범주 매퍼가 전체train을 사용한 역사적 예외가 남아 있다. 새 판별기의 학습·내부 교차 예측·별도 검색 진단은 선박을 분리했지만, 기존 비교 경로의 한계가 모두 사라진 것은 아니다.

실험별로 기준·소스·입력을 고정하고 대조군과 비교했다. 실패 후 기준을 낮추지 않았으며, 기존 v12 소스·가중치·ZIP을 보존했다. 호출부호 조회와 train/test 동일 선박 조회는 사용자 방침에 따라 계속 제외했다.

## 6. 남은 오답을 통해 확인한 병목

최신 제원 실험에서 같은 fold1·4의 testlike 중 실제 한글이 남은 v12 오답324행을 분류했다. 변형 행의 집계이므로324척의 독립 선박을 뜻하지 않는다.

| 현재 제원 보정이 회복하지 못하는 이유 | 행 수 |
|---|---:|
| 정답이 고정 상위20 밖 | 51 |
| v12 승자와 정답의 인코딩된 제원 특징이 같음 | 142 |
| 같은 제원인 다른 후보가 정답보다 높은 기본 확률을 가짐 | 40 |
| 고정한 보정 배율로 역전할 수 없음 | 24 |
| 정답을 아는 가상 제원 보정이라면 회복 가능 | 67 |
| **합계** | **324** |

합쳐서182행은 새 모델의 넓은 제원 구간 특징만으로 정답과 앞선 후보를 구분하지 못했다. 이는 모든 원시 입력이나 이름 근거까지 같다는 의미는 아니다. 51행은 재판별 상위20 밖이므로 그 후보 집합 안에서 점수만 바꿔서는 복구할 수 없다.

정답을 아는 가상 보정은 현재 후보 집합·구간화·보정 폭에서0.926812였다. **실제 달성 점수나 Public 예측, 다른 모델의 상한은 아니다.** 초기 문서의 특정 규칙 정확도0.425 등도 정보 이론적 상한으로 해석하지 않는다. [진단·사례](../experiments/context_density_v1_limits.json)

## 7. 현재 상태와 남은 과제

| 항목 | 현재 상태 |
|---|---|
| 채택 모델 | v12 |
| 실제 최고 Public | **0.9065951735** |
| 서버 실행 시간 | **9분51초** |
| 목표와 차이 | **0.0634048265** |
| 실제 제출 | 9회 |
| 제출 패키지 | [v12_encoder.zip](../dist/v12_encoder.zip), 약6.98GB |
| v12 이후 개선안 | 실행한 후보 모두 기각 |
| 호출부호·동일 선박 조회 | 제외 유지 |

다음 실험에서 해결해야 할 대상은 **상위20 후보 누락**, **제원이 비슷한 후보 사이의 이름 구별**, **톤수가 남은 약칭에서의 회귀**다. 같은 입력·같은 후보에 학습량이나 혼합 비중을 늘리는 방식은 지금까지 순증 근거를 얻지 못했다.

이 방향이 v12를 넘거나 목표0.97에 도달한다는 방법론적 근거는 아직 확보하지 못했다. 새 가설은 검증 선박 분리, 원본 정답 보존, 약칭·결측별 회복과 손실, 별도 변형 검증을 함께 평가해야 한다.
