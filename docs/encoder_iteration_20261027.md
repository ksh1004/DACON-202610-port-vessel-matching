# v11 실제 제출 후 다국어 인코더 실험

> **2026-10-28 실제 결과 추가:** 사용자 보고 v12 Public **0.9065951735**, 서버 **9분 51초**. v11 대비 **+0.0026315790**, 시간 **+20초**로 현재 확인된 최고 Public이다. 기록된 제출은 9회, 목표 0.97까지 0.0634048265 남는다. 아래 실험 설계는 2026-10-27 준비 당시 기록이다.

작업일: 2026-10-27. 사용자 보고 v11 Public **0.9039635945**, 서버 **9분 31초**다. 현재 최고 Public이며 목표 0.97은 미달이다. 호출부호 조회·train/test 동일 선박 조회는 계속 제외한다. 기존 v11·v10·v8·v7 모델과 ZIP은 보존하며, 이번 작업에서 실제 test 조회나 대회 제출은 하지 않는다.

## 새 가설과 구성

기존 Qwen 후보 판별기에 더해 다른 구조의 다국어 교차 인코더가 보완 신호를 줄 수 있는지 시험한다. [제작자 모델 카드](https://huggingface.co/BAAI/bge-reranker-v2-m3)에서 표준 Transformers 추론을 지원하는 BAAI/bge-reranker-v2-m3를 확인했다. 리비전 `953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e`의 공식 가중치·토크나이저·모델 카드만 받았으며 원격 Python은 실행하지 않는다. 제작자 카드의 라이선스는 Apache-2.0이다.

- `src/encoder_pair.py`: 한 행의 이름·톤수·선종·국적·국제총톤수와 그 이름에서 생성한 음역 최대 4개를 질의로, 후보의 이름·톤수·선종·국적을 문서로 사용한다. ID·호출부호·정답 ID는 입력에 넣지 않는다.
- `src/encoder_experiment.py`: 기존 strict 학습 fold 후보에서만 음성을 고른다. 학습 fold 전용 LightGBM 상위 5개 + 문자열 혼동 2개, 정답 1개로 학습한다. 원본·증강의 학습/검증 선박 중복은 0척이다.
- LoRA rank 8 / alpha 16 / dropout 0.05, query·key·value 및 분류 헤드 학습, 학습률 1e-4, 2,400개 그룹, 그룹 배치 2, 고정 1 epoch, 시드 42다. 최대 256토큰, 우측 패딩을 쓴다.
- 분류 헤드의 학습 정밀도와 저장 정밀도가 달라지지 않도록, LoRA 병합 → BF16 변환 → 저장 → 재로딩한 모델로 검증한다.
- 평가 후보는 기존 v8/v11과 동일한 상위 20개다. 정답 후보를 강제로 추가하지 않는다. 신경망 전체 비중은 25%로 고정하고 비한글 입력은 기존 경로를 유지한다.
- 두 안만 비교한다: v8 75% + 새 인코더 25%, v8 75% + v11 Qwen 12.5% + 인코더 12.5%. 비율 탐색은 하지 않는다.

## 사전 기준

[encoder_iteration_protocol.json](../experiments/encoder_iteration_protocol.json)에 학습 결과 확인 전에 고정했다. 이미 반복 사용한 검증 세트에 대한 탐색이므로 이 조건을 통계적 보장으로 간주하지 않는다.

1. fold 1·2를 먼저 평가한다. 합산 testlike 순증 v11 대비 +0.001 이상, 각 fold 순증 -0.002 이상, hard 한글 순증 -0.002 이상, 원본 정답 손실 최대 1행을 요구한다.
2. few-shot 선박을 제외한 fold 1에 7개 새 변형을 만들고, 범주 매퍼·후보 검색까지 학습 fold로 분리한 같은 기준 모델에서 비교한다. 평균 정확도 하락은 최대 0.002다. 이 값은 공식 지표가 아니다.
3. 통과하면 나머지 fold로 확대한다. 최종 후보는 전체 testlike +0.001 이상, hard 한글 하락 최대 0.002, OOF 하락 최대 0.0006, 3/5 이상 fold 순증을 요구한다. 단독 인코더를 우선한다.

## 1차 모델 기각과 발음 키 보강

모델 로딩·LoRA/헤드 업데이트·유한 손실·병합 BF16 추론을 확인했다. 표본 16쌍 144토큰의 초기 3회 업데이트는 약 3.0초, 측정 peak allocated 메모리는 2.91GiB였다. 전체 실행 시간·메모리의 보장값은 아니다. [초기 실행 로그](../experiments/run_bge_warmup.log)

일반 인코더는 fold 1·2에서 testlike가 +0.00246 올랐지만 hard는 0.85737 → 0.85018, 한 fold는 -0.00743으로 하락해 확대하지 않았다. 고정 평균도 hard 하락과 fold 조건을 통과하지 못했다. 특히 이름 변형과 톤수 결측이 겹친 hard 행에서 2행 회복·10행 손실이 났다. [1차 집계](../experiments/encoder_bge_v1_audit.json), [오류 진단](../experiments/encoder_plain_hard_diagnostics.json)

이에 기존 규칙 기반 한글/영문 발음 키를 질의와 후보에 명시했다. 예를 들어 키의 각 문자를 띄우고 단어 경계를 `|`로 표시한다. 이름 원문·제원·4개 음역을 함께 유지하며, 외부 사전이나 선박 조회를 추가하지 않는다. `src/encoder_phonetics.py`와 `src/encoder_phonetic_experiment.py`로 기존 입력과 분리했다. 이 수정의 결과를 보기 전에 [새 실험 기준](../experiments/encoder_phonetic_protocol.json)을 저장했다.

발음 키 인코더 단독은 초기 두 fold에서 한 fold -0.0087로 탈락했다. **Qwen/인코더 고정 평균만** testlike +0.002445, 각 fold +0.005526/-0.000900, hard 개선으로 확대 조건을 통과했다. 전체 결과가 나중에 좋아져도 초기 탈락 조건을 없애지 않았다. [고정한 두 fold 결과](../experiments/encoder_bge_phonetic_screen_snapshot.json)

## 별도 변형 진단

few-shot 선박을 제외한 fold 1의 228개 기록에 7개 변형을 적용한 1,596행을 사용했다. GT/IGT 개별 결측, GT의 0.5/1.5배 충돌, 첫/마지막 단어 생략과 생략+톤수 결측을 포함한다. 범주 매퍼·검색·음성 선별까지 외부 검증 선박과 분리한다. 입력의 실제 이름 변경 여부도 구분한다.

v11의 평균 정확도는 **0.805138**, 새 고정 평균은 **0.804511**로 -0.000627이다(18행 회복·19행 손실). 사전 하락 허용치 -0.002는 통과했지만 새 표본에서 개선을 입증한 것은 아니다. 이 진단은 공식 가중 지표와도 다르다. [별도 변형 결과](../experiments/fresh_pairs_f1_encoder_bge_phonetic.json)

## 전체 5-fold 결과와 v12 선택

최종 구성은 **v8 75% + v11 Qwen 판별기 12.5% + 발음 키 BGE 판별기 12.5%**다. 비한글 입력은 기존 경로를 쓰며 신경망 총 비중 25%, 후보 20개를 유지한다. 새로운 비율 탐색은 하지 않았다.

| 지표 | v11 | v12 | 차이 |
|---|---:|---:|---:|
| testlike | 0.908762 | **0.911871** | +0.003109 |
| hard | 0.854115 | **0.857935** | +0.003820 |
| 원본 OOF | 0.997693 | **0.997693** | 0 |
| testlike 한글 | 0.870437 | **0.874878** | +0.004442 |
| 톤수 결측 한글 | 0.973971 | **0.983207** | +0.009236 |
| 단어 생략 한글 | **0.827036** | 0.821998 | -0.005038 |
| 생략+결측 한글 | 0.552477 | **0.575147** | +0.022670 |

testlike는 기존 시나리오 비율(원본 44%, 결측 14%, 생략 23%, 둘 다 19%)을 사용한 로컬 대체 지표다. 실제 test의 구성비가 확인된 것은 아니다. 5개 fold 중 **4개 개선**, 순증은 순서대로 +0.002403 / +0.005526 / -0.000900 / +0.004407 / +0.003614다. 선박 단위 paired bootstrap 2,000회의 순증 95% 구간은 **[-0.000439, +0.007000]**으로 0을 포함한다. [전체 집계](../experiments/encoder_bge_phonetic_audit.json)

few-shot에 나온 선박 전체를 제외해도 testlike **0.908486 → 0.912114**다. 원본 정답 회복·손실은 각각 0행이다. 변형 3,573행은 **60행 회복·28행 손실**, hard 5,382행은 **22행 회복·9행 손실**이다. 결측은 +11행, 단어 생략은 -6행, 생략+결측은 +27행이다. 단순 행 수는 시나리오 가중 testlike와 다르다. [변화 집계](../experiments/encoder_change_audit.json)

초기 두 fold·별도 진단·전체 5-fold 조건을 모두 통과한 고정 평균을 v12로 선택했다. 인코더 단독은 전체 값이 좋아도 초기 탈락을 유지한다. [선택 근거](../experiments/encoder_iteration_selection.json)

## 배포 구현과 검사

- `src/encoder_views.py`: 기존 v11 모듈을 보존하고 두 판별기를 로컬에서 읽어 결합한다. PEFT는 학습에만 필요하며 제출 추론에 포함하지 않는다.
- `tools/train_encoder_final.py`: 전체 공식 train에서 선박명 원본·증강 후보를 생성하고 고정 2,400개 그룹으로 최종 학습한다. 기존 v11 최종 Qwen 가중치를 보존해 복사하고 새 BF16 인코더를 추가한다. 최종 학습·저장 285.5초.
- `tools/check_encoder_runtime.py`: 병합·저장·재로딩한 두 판별기의 점수가 저장된 fold 3 OOF와 정확히 같고 결합 예측도 일치한다. 그룹 분할·셔플·단독 실행도 통과했다. [검사 로그](../experiments/run_v12_runtime.log)
- 저장 토크나이저의 27,360개 검증 후보 쌍 토큰이 CV 캐시와 정확히 같음을 확인했다. ID·호출부호 변경과 톤수 int/float 표현에 대한 입력 불변성도 통과했다. [토큰 검사](../experiments/run_encoder_phonetic_tokens.log)
- `tools/build_package.py`와 `tools/script_template.py`는 `encoder_views.json` 구성을 지원한다. `tools/release_encoder_iteration.py`는 사전 선택 조건과 소스 해시를 확인한 뒤 ZIP·행 독립성·실제 두 신경망 호출·CRC를 검사한다. 업로드 기능은 없다.

임시 폴더에 푼 패키지의 train 유래 3,000행 실행은 **177.0초**, 셔플 부분집합 300행과 단독 행 3회 예측 일치도 통과했다. 이 표본의 정확도는 학습에 사용한 행을 포함하므로 성능 지표로 사용하지 않는다. 이전 v11의 로컬 245.7초와는 측정 시점이 달라 실행 시간 단축의 인과 근거로 사용하지 않는다. [전체 실행 로그](../experiments/run_v12_package.log)

## 해석과 남은 과제

**2026-10-28 사용자 보고 v12 Public은 0.9065951735, 서버 시간은 9분 51초다.** v11의 0.9039635945보다 +0.0026315790 올라 현재 확인된 최고다. 목표 0.97까지 0.0634048265 남는다. 원본 OOF가 높은 것만으로 실제 노이즈에 대한 성능을 판단하지 않는다.

이번 개선은 톤수 결측에 집중되고 톤수가 남은 약칭은 악화했다. 별도 진단에서도 평균이 소폭 하락했다. 또한 반복 사용한 검증 세트에 대한 탐색이며, 비교에 쓰인 기존 v8 후보 검색 범주 매퍼의 전체 train 사용 예외가 남는다. 새 판별기의 학습 후보와 별도 진단의 검색은 fold로 분리했지만 이 한계까지 없앤 것은 아니다. 따라서 +0.003109를 Public 예상 상승치로 옮기지 않는다.

다음 우선순위는 톤수가 남은 약칭에서 새로 틀린 행의 후보 구별 근거를 조사하고, 학습량이나 혼동 후보를 바꾸는 실험을 별도 사전 기준으로 검증하는 것이다. 실제 test 행 수는 여전히 비공개다. 이번 서버 시간은 사용자 보고값이며 후속 모델의 실행 시간 보장으로 사용하지 않는다.
