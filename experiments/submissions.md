## 제출 원칙

- **진단용 제출은 하지 않는다.** 결정은 선박 단위 OOF CV로 하고, CV가 의미 있게 오른 모델만 제출한다
- 제출할 때는 가능하면 **한 요소만 바꿔서** 점수 변화를 해석할 수 있게 한다
  - 한글 처리만 바꾼 제출의 변화량 = `0.7 × Δ한글` → test 한글 정확도 변화를 그대로 역산할 수 있음

- 베이스라인 대비 비한글과 한글이 함께 바뀌므로 Public 변화를 두 요소로 나눌 수는 없음
- 이후 제출은 비한글 모델을 고정하고 한글 처리만 바꿀 예정 → 그때부터 변화량이 한글 성능으로 바로 해석됨

## 제출 3~5로 본 test 한글의 성격 (2026-10-23 분석)

- 비한글 test 정확도를 0.998로 두면 test 한글 추정치: v3 0.631 → v4 0.756 → v6 0.855 (CV는 0.966 / 0.966 / 0.994)
- 스트레스 시나리오 혼합으로 세 값을 함께 맞춰 보면 **원본 35%, 톤수 결측 25%, 단어 생략 25%, 톤수 결측+단어 생략 15%** 가 세 제출 모두를 ±0.025 이내로 설명함
  - v3: 예측 0.606 / 실제 0.631, v4: 0.770 / 0.756, v6: 0.853 / 0.855
- 이 해석이면 v6의 남은 손실(약 0.145) 거의 전부가 **단어 생략(약칭) 행**에서 나옴
- train 비한글의 실제 노이즈: 선박 단위로 35%가 글자 삭제·중복·순서 바뀜 1~2회, 단어 생략은 0건, 개명 추정 약 0.8%. train 한글은 오타·톤수 결측이 없음 → test 한글에만 노이즈가 들어갔을 가능성

## 제출 6 (v7) 해석 (2026-10-26)

- Public +0.0019 (v6 0.8979 → v7 0.8998), testlike 예측은 +0.007
- testlike와 Public의 차이: v6 설정 +0.003 (Public이 높음), v7 -0.002 (Public이 낮음) → **testlike의 오차 폭은 약 ±0.003**
- Public 점수의 해상도: 가짜 test(train 표본 3,000행)의 한글 비율로 보면 public 한글 행은 300행 이하 → **한글 1행 = 0.0023 이상**. 0.005 이하의 차이는 Public으로 구분하기 어려움
- 정확한 행 수를 점수 소수점으로 역산하려 했으나 (가중 평균 두 형태 모두) 일치하는 해가 없음 → public 부분집합이나 반올림 방식이 다른 것으로 보임
- 결론: v7은 최고 점수지만 개선 폭은 Public 노이즈 수준. 이후 결정은 계속 로컬 지표(testlike, hard, OOF)로 하고, **로컬에서 +0.005 이상**일 때만 제출
